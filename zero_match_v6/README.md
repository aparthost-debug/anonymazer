# Zero-Match Enterprise Anonymizer v6.1

Демонстрационный локальный контур обезличивания табличных данных. **Не даёт заключения о соответствии 152-ФЗ** —
это инструмент для расчёта метрик и подготовки материалов к экспертной оценке.

## Запуск
```bash
pip install -r requirements.txt
streamlit run app.py
python tests/run_tests.py          # тесты (pytest не обязателен)
```

## Что внутри
| Модуль | Назначение |
|---|---|
| `anonymizer/pipeline.py` | конвейер: токенизация, категории, перестановка Саттоло + шум (ε-LDP), биннинг с автоподбором, зачистка текста, Марков, подавление |
| `anonymizer/pii_detect.py`, `text_clean.py` | единый детектор ПДн (контрольные суммы ИНН/СНИЛС/Luhn/IBAN, уровни уверенности), классификация колонок по токенам, NER (spaCy/natasha) |
| `anonymizer/metrics.py` | k, l-разнообразие, t-близость, атака связывания, полезность, смещение от удаления строк |
| `anonymizer/benchmark.py` | ML-бенчмарк (парное сравнение) и оптимизатор обобщения |
| `anonymizer/policy.py`, `inventory.py`, `evidence.py` | политики выпуска, инвентаризация без значений, манифест с хеш-цепочкой и подписью |
| `anonymizer/workspace.py` | пользователи, проекты, «четыре глаза», согласование, подписанный журнал (SQLite); принимает на согласование только изолированные прогоны с заполненной карточкой |
| `anonymizer/dossier.py` | карточка обезличивания: состав ПДн, субъекты, основание, места хранения, оценка достаточности (Приказ РКН № 140, Прил. 1, п. 1) |
| `anonymizer/acts.py` | черновики локальных актов (порядок, оценка достаточности, правила по методам, учёт операции) и записка получателю |
| `anonymizer/isolation.py` | изолированный режим: после запуска исходник и связь строк удаляются из результата и сессии |

## Что важно знать
* **Экспорт блокируется**, если не пройдены обязательные проверки (k; l/t — по настройкам; остаточные ПДн; необработанные
  прямые идентификаторы). «Предупреждения» (ok_warn) не блокируют. При включённом release gate выгрузка должна быть
  утверждена в проекте — привязка идёт к sha256 именно скачиваемого CSV.
* **Seed** не попадает ни в сохранённую конфигурацию, ни в отчёты, ни в манифесты.
* **Первый запуск workspace:** токен первичной настройки лежит на сервере (`$ZERO_MATCH_HOME/bootstrap_token.txt`).
  Ключ Ed25519 создаётся при создании администратора; открытый ключ (`*.pub.pem`) храните **отдельно от сервера**.
* **ARX:** нужна ваша Java-обёртка; запуск только из `ZERO_MATCH_ARX_DIRS`, отключается `ZERO_MATCH_DISABLE_ARX=1`.
* Исходная таблица и секретное соответствие строк (`pair_pos`) живут в памяти сессии для сравнения «до/после»;
  кнопка «Очистить сессию» их удаляет. Ни то, ни другое не пишется в файлы и отчёты.
* Данные рабочего пространства (`zero_match_data/`) в репозиторий не коммитьте.

## Приказ РКН № 140 (в силу с 01.09.2025): что реализовано
* **Карточка обезличивания** (раздел в интерфейсе, сохраняется в проекте, снимок фиксируется в каждом прогоне).
  Автозаполнение подсказывает состав и обработку колонок; **вывод о достаточности метода делает только человек**.
* **Локальные акты** (ZIP, вкладка «Внутренние документы»): порядок обезличивания, оценка достаточности, правила по методам
  (пп. 4, 10, 11, 12 Прил. 2), карточка учёта операции. Это черновики для юриста/ответственного за ПДн.
  В акте о перемешивании стоит пометка «ТРЕБУЕТ РЕШЕНИЯ»: Прил. 1, п. 2(4) говорит о перестановке на заданное число
  позиций, а реализован случайный цикл (Саттоло).
* **Раздельное хранение:** в изолированном режиме (включается сам для загруженных данных) после запуска из результата и
  сессии удаляются исходная таблица и секретная связь строк. Графики строятся по агрегатам, посчитанным при запуске.
  ML-бенчмарк в этом режиме выполняется «при запуске», до удаления. Python не гарантирует затирание памяти — для
  гарантий разделяйте контуры (отдельный процесс/хост).
* **Документы отдельно от данных:** вкладка «База и экспорт» отдаёт только данные и записку получателю (без методов);
  отчёты, акты и журналы помечены «ВНУТРЕННИЙ ДОКУМЕНТ» и лежат на отдельной вкладке.
* **Политики и согласование:** проверки «изолирован ли исходник» и «заполнена ли карточка» входят в политики выпуска;
  на согласование в workspace не принимаются прогоны в режиме разработки или без заполненной карточки.

Чего пока нет: режим передачи обезличенных данных в госсистемы (п. 9.1 ч. 1 ст. 6), SSO/MFA, шифрование БД и ключей,
плейбук инцидентов. Это не юридическая консультация — формулировки актов проверьте с юристом.
